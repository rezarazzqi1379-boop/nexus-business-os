## Entry for ChatGPT, Codex and other runners

1. Read `.nexus/prompts/NEXUS_GLOBAL_KERNEL_V1.md`, this file, and `docs/NEXUS_PLATFORM_BUILD_CONTRACT_V1.md`.
2. Recover canonical project source references; verify current branch, HEAD and exact-head CI.
3. Read `state/nexus_parallel_board_v1.json` and validate it. A task is not done merely because another agent claims it is.
4. Claim one unblocked lane in an isolated branch/worktree. Do not overwrite another lane's evidence.
5. Produce a bounded artifact, provenance, diff, test evidence and rollback.
6. Reconcile results via review. Update shared state only with grounded references and commit.
7. Re-read committed state. Record CI outcome and unknowns. No claims of cross-chat synchronization without actual bootstrap.

## Independent parallel lanes

- STEEL_COMMERCIAL: qualified buyer / current need / stock / relationship evidence, not just lead volume.
- INDUSTRIAL_PROJECTS: Hydrotester, KCl/SOP, Can Forming, Heat Treatment, each strictly isolated.
- FREELANCE_DEALS: marketplace candidates, identity, need, human review, Deal Room.
- ADAPTER_RESEARCH: benchmark reusable open-source components; do not install by default.
- ENGINEERING_QA: synthetic simulations, adversarial fixtures, regression and CI.
- GOVERNANCE_STATE: registry reconciliation, evidence provenance, permissions, cost and audit.

## Continuous simulation loop

Use `nexus_simulation.py` and its tests for a deterministic dry-run. Seed only synthetic data.
For each iteration record: baseline commit, candidate commit, fixture version, tests,
false-accept count, false-reject count, runtime and model-token cost if actually measured.
Do not claim continuous execution without a scheduler and verified run history.
Never store credentials, confidential raw mail or personal data in fixtures.

## Invention rules

A proposal must state hypothesis, expected measurable commercial/engineering impact,
falsifier, minimal experiment, cost ceiling, rollback and project scope.
Only adopt after positive and adversarial tests, exact-head green CI and human approval where required.
Self-improvement is versioned code/policy/eval changes, not changes to the model weights.

## Stop rules

Red exact-head CI; conflicting canonical authority; cross-project contamination;
unreviewed customer identity; missing provenance; stale required evidence; unapproved external action.
No merge, deploy, outreach, publishing, purchases, production writes or paid credits without exact approval.
