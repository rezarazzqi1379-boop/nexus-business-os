# برش دوم: سهمیهٔ پایدار و TED؛ اتصال UNGM مسدود

مبنا: main در `0e91724466688d1932b1f6a70cd9661b56cba7d2`.
مرحلهٔ فعلی: ساخت، آزمون و آزمایش زندهٔ محدود با مجوز دقیق مالک؛ مسئول اجرا Codex است.

## نتیجهٔ بررسی دسترسی

در ۲۰۲۶-۱۰-۲۹، جست‌وجوی رسمی با عبارت
`site.ungm.org terms conditions automated access API robots scraping`
به https://www.ungm.org/Public/Pages/Terms رسید. بندهای ۵.۲ و ۵.۳ استفادهٔ
تجاری و درج محتوا در سامانهٔ بازیابی را محدود می‌کنند و اجازهٔ کتبی را مطرح
می‌کنند. این بررسی مجوز دریافت تجاری UNGM را احراز نکرد.
هیچ crawling، probe اتصال‌دهنده، حساب یا ایمیلی انجام نشد.

`UNGMConnector` فقط guard مسدودکننده است؛ adapter فعال یا parser آزموده‌شدهٔ
UNGM محسوب نمی‌شود. رفع مانع نیازمند اجازهٔ مناسب ارائه‌دهنده یا انتخاب
منبع رسمی جایگزین با شرایط مناسب است. مجوز مالک جایگزین مجوز ارائه‌دهنده نیست.

## تغییر قابل اجرا

همان `AutonomyStore` دو جدول برای برنامهٔ immutable آزمایش و رزرو HTTP دارد؛
کنترل‌پلین یا زمان‌بند جدید ساخته نشده است. هر برنامه شامل project، دو شناسهٔ
منبع، زمان شروع، فاصلهٔ حداقل ۳۰۰ ثانیه، ۳ پنجرهٔ tick و سقف ۶ تلاش است.
رزرو با `BEGIN IMMEDIATE` پیش از transport commit می‌شود. تغییر مشخصات همان
شناسهٔ آزمایش رد می‌شود. crash قبل/حین دریافت رزرو را مصرف‌شده و نامطمئن
باقی می‌گذارد؛ هیچ refund یا ادعای exactly-once وجود ندارد.

`TrialTransport` دریافت موجود و محدود بانک جهانی را instrument می‌کند؛
transport تولیدی همان URL ثابت، timeout، سقف bytes و عدم redirect موجود را دارد.
`TrialMonitoringRuntime` از worker، supervisor، lease و retry فعلی استفاده می‌کند.
برای fixture و live همان تفکیک قبلی DB و برچسب حفظ می‌شود.
کد custom transport فقط ورودی trusted تست است و نباید retry/redirect داخلی داشته باشد.

برای استفاده، میزبان باید یک برنامه با ID ثابت روی همان DB تنظیم کند، سپس
worker آزمایش را برای tickهای ۰ تا ۲ در پنجرهٔ متناظر فراخوانی کند.
همهٔ retryها همان ID و DB را مصرف کنند؛ جابه‌جایی DB یا ساخت ID تازه آزمایش
جدید است و نباید برای تمدید خودکار سقف به‌کار رود. زمان‌بند دائمی یا host
آزمایش زنده در این تغییر فعال نشده است. ذخیرهٔ DB و journal الزامی است.

## شواهد و محدودیت پذیرش

آزمون‌ها: ۳ tick با clock ثابت، ۶ رزرو پس از restart، رقابت هم‌زمان،
crash قبل و حین transport، شکست و retry، پایان پنجره، تغییر برنامه،
scope منبع/پروژه و اتصال worker موجود تا supervisor.
این‌ها آزمون آفلاین هستند؛ رزرو مصنوعی منبع دوم، دادهٔ واقعی یا استقلال
UNGM را اثبات نمی‌کند. آزمایش واقعی چندمنبعی هنوز اجرا نشده است.
آزمون frozen هرگز `multi_source_live_proven=true` تولید نمی‌کند.

## جایگزین مجاز: TED

مالک بررسی منبع جایگزین و سپس آزمایش زندهٔ مشخص را مجاز کرد.
مستندات رسمی https://docs.ted.europa.eu/api/latest/search.html دسترسی بدون
احراز هویت و بازاستفاده را توضیح می‌دهد؛
https://ted.europa.eu/en/legal-notice بازاستفادهٔ تجاری از آگهی‌ها را با
استثناهای حقوق اشخاص ثالث بیان می‌کند. تنها publication-number درخواست می‌شود؛
عنوان اشخاص، تماس، ایمیل، سند پیوست یا لینک بازگشتی fetch نمی‌شود.

درخواست ثابت: POST فقط‌خواندنی به https://api.ted.europa.eu/v3/notices/search
با `FT~steel`، ۳ نتیجه، page=1 و PAGE_NUMBER. کد HTTP همان timeout، سقف
۶۴ KiB و منع redirect/retry خودکار را دارد. group منشأ انتشار EU با بانک
جهانی جداست؛ این جدایی، استقلال هر ادعای تجاری را اثبات نمی‌کند.
`run_source_trial.py` میزبان محدود ۳ tick پنج‌دقیقه‌ای است و پس از آن خارج
می‌شود. برنامه و mode در ledger ثابت‌اند؛ همان DB و ID در restart حفظ می‌شوند.
پس از checkpoint موفق، همان source/tick مجدداً HTTP نمی‌فرستد.

در آزمایش اولیه tickهای ۰ و ۱ به‌اشتباه `checkQuerySyntax=true` داشتند؛
پاسخ TED معتبر ولی خالی بود. این اشتباه تشخیص داده شد و میزبان با همان
DB/ID متوقف و restart شد؛ چهار رزرو قبلی refund نشدند. دو تلاش باقی‌مانده
برای tick سوم با `checkQuerySyntax=false` مصرف شدند. نمونهٔ رسمی درخواست
در https://op.europa.eu/en/web/ted-reusers-workshops/questions_and_answers_2023_12_14
نیز این مقدار false را برای جست‌وجو نشان می‌دهد.
بنابراین دریافت پاک و غیرخالی TED در هر سه tick نباید ادعا شود؛ نتیجهٔ
واقعی هر tick و اصلاح پروتکل باید همراه ledger گزارش شود.

گام بعد: بررسی شواهد نهایی همین آزمایش و پذیرش فنی بر مبنای محدودیت‌های ثبت‌شده.
دو مناقصهٔ متفاوت نباید به‌عنوان corroboration یک ادعا شمرده شوند.
مقایسهٔ conflict برش اول همچنان CLAIM است؛ HOLD و منع اقدام تجاری پابرجاست.

نگهداری نشده‌اند. `verify_source_trial.audit` فقط ساختار ledger، scope، زمان و
سقف را با همین رکوردها ممیزی می‌کند و بازاجرای مستقل پاسخ خام نیست.

گام پذیرش باقی‌مانده: پس از بررسی PR، در صورت مجوز تازه یک اجرای پاک با
تنظیم اصلاح‌شده برای هر سه tick انجام شود. هیچ سهمیهٔ تازه خودکار ایجاد نشود.
