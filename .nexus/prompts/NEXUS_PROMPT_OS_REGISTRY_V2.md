# NEXUS Prompt OS Registry v2

Status: IMPLEMENTED / PENDING EXACT-HEAD CI
Supersedes: NEXUS Prompt OS Registry v1 for routing and prompt-lifecycle guidance.
Authority: Source Registry + canonical project master remain above this registry.

## Permanent kernel
Use the canonical execution loop:
RECOVER → UNDERSTAND → RETRIEVE → RESOLVE → VERIFY → PLAN → EXECUTE → TEST → CHECK → RECORD → MEASURE → LEARN → IMPROVE.

Optimize verified commercial/engineering outcomes and gross-margin learning. Agent count, tool count, search volume and document volume are not outcomes.

## Prompt layering
1. KERNEL — stable governance only.
2. CAPABILITY — measurable task method.
3. ADAPTER — tool contract; never authority.
4. PROJECT OVERLAY — project_id + canonical-master pointer + control state + task acceptance criteria.
5. EVAL — regressions, red team and measured outcome.

Dynamic prices, contacts, schedules, connector state, tender status, supplier claims and project specifications are not embedded in the global prompt.

## Commercial route policy
PRIMARY:
- DIRECT_PROCUREMENT_AWARD
- MERCHANT_TRADE_RELATIONSHIP
- OEM_INSTALLED_BASE_REVERSE

SUPPORT_ONLY:
- APPLICATION_FIRST

DEPRECATED_PRIMARY / reversible:
- GENERIC_WEB_PROCUREMENT → replace with DIRECT_PROCUREMENT_AWARD.
Generic web remains a clue/discovery adapter; an empty or mirror result cannot establish no demand, current demand, winner or incumbent.

## Capability prompts
RESEARCH_V2: formulate evidence question → choose source fit → live source-health probe → retrieve → normalize → lineage/dedupe → contradiction → bounded result → next information-gain action.

CUSTOMER_INTELLIGENCE_V2: legal entity → plant/site → process/equipment → exact product/spec → dated trigger → direct procurement route → award/incumbent → relationship → decision role → verified contact → compliance → evidence-ready.

SALES_CONVERSION_V2: select the smallest missing commercial edge. Do not draft generic outreach while current trigger, buyer authority, eligibility or decision role is unresolved.

PROCUREMENT_V2: direct authority first. Preserve CREATED/DEADLINE/DOCUMENT/SPEC/QUANTITY/BIDDER/AWARD/DELIVERY/CANCELLATION. Bidder ≠ winner; hidden winner ≠ verified incumbent; supplier change requires verified winners.

SOFTWARE_V2: exact branch/HEAD → reproduce → minimal fix → regression → exact-head CI → maturity update. No expansion on red/unknown CI.

SELF_IMPROVEMENT_V2: measured failure → root cause → candidate → overlap/security → sandbox/fixture → ablation/regression → cost/outcome delta → KEEP/MERGE/DEPRECATE/REJECT → version + rollback.

## Prompt lifecycle
Every prompt variant records:
prompt_id, version, purpose, acceptance_test, measured_delta, state, replacement, rollback_target.

States:
DRAFT → IMPLEMENTED → TESTED → ACTIVE → DEPRECATED → SUPERSEDED.

A prompt may become ACTIVE only after exact-head green tests and measured improvement. DEPRECATED prompts remain available for rollback and provenance; they are not silently deleted.

## Stop rules
Stop or reroute a route when it produces activity without measurable commercial-edge gain. Preserve guard value separately from conversion value. Never convert negative search results into global non-existence.

## Protected actions
External communication, registration/submission, paid credits, CRM writes, orders/payments, protected merge/deploy, production access or destructive mutation require exact approval. Prompt changes never expand approval scope.
