# نقشهٔ واقعی ۲۸ پلاگین ruflo در nexus-business-os

تاریخ بررسی: 2026-09-14. این سند صادقانه‌ست: هرچی واقعاً کار می‌کنه رو می‌گه، هرچی که فقط
تنظیمات/ادعا یا وابسته به چیزی‌که وصل نیست رو هم می‌گه — نه برعکس.

## نکتهٔ کلیدی که همه‌چیز رو تحت‌تاثیر قرار می‌ده

از قبل (با اسکرین‌شات واقعی `/mcp` توی همین پروژه) تایید شده که سرور MCP به‌نام
`claude-flow` (که `.mcp.json` اعلامش می‌کنه) توی این نسخهٔ Claude Code شما **وصل نمی‌شه** —
فقط ۷ کانکتور رسمی claude.ai (Gmail، Drive، Notion، Railway، Apollo، HubSpot، claude-in-chrome)
مجازن. یعنی هر پلاگینی که قابلیتش رو فقط از طریق ابزار MCP (`memory_*`, `swarm_*`,
`agent_*`, `neural_*`, `daa_*`, ...) عرضه می‌کنه، **در جلسهٔ واقعی شما غیرقابل‌دسترسه**،
صرف‌نظر از این‌که در `enabledPlugins` روشنه یا نه.

راه واقعی که کار می‌کنه (تست و تایید شده با واقعاً ذخیره کردن یه embedding ۳۸۴بعدی):
اجرای مستقیم CLI از طریق ابزار Bash: `npx ruflo@latest memory store/search ...` — این از
MCP رد نمی‌شه، مستقیم پردازش می‌شه.

دو چیز دیگه که مستقل از MCP کار می‌کنن:
- **Hooks** (PreToolUse/PostToolUse/SessionStart/...): اسکریپت Node ساده‌ان
  (`hook-handler.cjs`)، نیازی به MCP ندارن — همون‌هایی که statusline «Hooks 16/16»
  نشونشون داد.
- **Skills** (فایل‌های SKILL.md هر پلاگین): متن راهنمان که من می‌خونم و دنبال می‌کنم؛
  نیازی به MCP یا شبکه ندارن.

## جمع‌بندی صادقانه

- از ۲۸ پلاگین، فقط بخش «اسکیل» (راهنمای متنی) و «hook» (اسکریپت Node محلی) همه‌شون واقعاً
  فعالن — این‌ها همون چیزین که باعث شدن «Hooks 16/16» رو ببینید.
  - **هیچ‌کدوم از این‌ها به‌خودی‌خود کد یا منطق تازه‌ای اجرا نمی‌کنن** — صرفاً فایل متنی/راهنمان
    که من (Claude) در حین کار می‌خونم و طبقش رفتار می‌کنم؛ چیزی نیستن که مستقل از من چیزی
    «بسازن» یا «تصمیم بگیرن».
- قابلیت واقعی و اثبات‌شده: اجرای مستقیم CLI (`npx ruflo@latest <command>`) از طریق Bash —
  همینی که برای ذخیرهٔ حافظه تست و تایید شد.
- ruflo-federation و ruflo-business-pods ذاتاً به «چند نصب دیگه» یا «حالت live» نیاز دارن که
  وجود ندارن — روشن‌بودنشون در `enabledPlugins` چیزی رو در عمل عوض نمی‌کنه.
- ruflo-loop-workers نمی‌تونه به‌عنوان فرآیند پس‌زمینهٔ دائمی کار کنه، چون این پلتفرم (device_bash /
  Claude Code session) هیچ پردازش پس‌زمینه‌ای رو بین فراخوانی‌ها زنده نگه نمی‌داره.
- **هیچ‌کدوم از این ۲۸ پلاگین یه سیستم «خودمختار» جدید نساخته و نمی‌سازه** — این دقیقاً همون
  چیزیه که پروژه‌ی خودتون هم صریح رد کرده (`REJECTED: autonomous AI-to-AI bridge`).
