### P2-1. SV-reversals-238 lookahead creates silent false negatives, and one is pinned by the new test

**Where:** `nexus_checks/superseded_values.py:55` and `evals/test_nexus_checks.py:143`.

The lookahead `(?![- ]?(?:line|lines|سطر|行)\b)` suppresses any `238` followed by "line", "lines", "سطر" or "行", whatever the context. The "bad" fixture in the new test is `"238-line rolling duty: 238 reversals per hour"`. It is flagged only because of the second `238`. The first phrase alone is not flagged:
```
PR100                         main
pass '238-line rolling duty'  FLAG
pass '238 line duty'          FLAG
pass 'duty of 238 lines/h'    FLAG
pass '238 lines/h on the mill' FLAG
pass '238 LINE duty'          FLAG
pass '238行' / '238 行'       pass / FLAG
FLAG '238‑line duty' (U+2011 hyphen), FLAG '238–line duty' (en dash)   <- still false positives
FLAG '۲۳۸ رفت‌وبرگشت در ساعت'  (Persian digits OK, _FA normalisation works)
```
There is also a false negative in Chinese that predates this PR and is present on main. Han characters are `\w`, so `\b238\b` never matches when a Han character touches the digits:
```
pass '往复次数 238次/小时'   pass '反转次数：每小时238次'   (both main and PR100)
pass '齿轮箱8至16吨'  (SV-gbx-weight-8-16 has no 至 in its alternation)
```
Today's impact is low: `docs/procurement` has no Han text (`git grep -lP "\p{Han}" docs/procurement` returns nothing). The Chinese RFQs are the planned next output, though.

**Fix:**
- Narrow the exemption to file-length context, for example `238[- ](?:line|lines)\b(?=[^\n]{0,20}(?:file|test|added|code|diff))`. Alternatively, use a line-level exemption on `\.py|test file|lines added`.
- Replace `\b` with `(?<!\d)` / `(?!\d)` so that CJK-adjacent digits match.
- Add `至` to the weight rule.
- Change the test so the "bad" line has the duty phrase alone.
