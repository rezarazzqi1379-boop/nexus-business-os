# راهنمای استفاده از Expert Foundry

## روش پیشنهادی برای رضا و کارکنان

فایل‌های کارخانه را ابتدا بدون تغییر نگه دارید. یک کپی از فایل CSV، JSON یا XLSX را
برای بررسی انتخاب کنید. فایل اصلی نباید ویرایش یا جایگزین شود.

هر ردیف باید پروژه، شماره ذوب، نوع داده، نام متغیر، مقدار، واحد، زمان، محل مدرک و
توضیح داشته باشد. الگوی CSV در `.nexus/expert_foundry/FACTORY_ROWS_TEMPLATE.csv`
قرار دارد.

چهار نوع داده پذیرفته می‌شود:

- `MEASUREMENT`: عدد یا نتیجه ثبت‌شده توسط دستگاه/آزمایشگاه
- `OPERATOR_OBSERVATION`: مشاهده یا تجربه اپراتور، نه واقعیت تأییدشده
- `INTERPRETATION`: برداشت یا تحلیل مهندس
- `HYPOTHESIS`: فرضیه دارای شاهد، جایگزین و آزمون ابطال

## مرحله اول: فقط پیش‌نمایش

در PowerShell و از پوشه پروژه اجرا شود:

```powershell
.\scripts\expert_foundry_intake.ps1 -InputFile "C:\path\heat-data.xlsx"
```

حالت پیش‌فرض `PREVIEW ONLY` است و چیزی ذخیره نمی‌کند. خروجی، ردیف‌های پذیرفته،
ردشده، تکراری، واحدهای مبهم و شماره‌ذوب‌های ناقص را نشان می‌دهد.
اگر `.venv` در clone جاری وجود ندارد، مسیر محیط معتبر را با گزینه `-PythonPath`
مشخص کنید؛ هرگز از Python خام روی PATH استفاده نکنید.

## مرحله دوم: ثبت پس از بازبینی

فقط پس از بررسی preview:

```powershell
.\scripts\expert_foundry_intake.ps1 -InputFile "C:\path\heat-data.xlsx" -Commit
```

در این حالت فایل خام با SHA-256 در vault ذخیره می‌شود و رکوردهای پذیرفته‌شده به
دفتر hash-chain افزوده می‌شوند. ingestion هیچ recipe، setpoint یا دستور تجهیزات
تولید نمی‌کند.

## روش ساده‌تر در این پروژه

رضا یا کارکنان می‌توانند فایل خام، عکس برگه آزمایش یا توضیح اپراتور را به همین
تسک تحویل دهند. تا وقتی واحد، زمان، heat ID یا منبع روشن نباشد، داده فقط به‌عنوان
ورودی بررسی‌نشده باقی می‌ماند و وارد تحلیل قابل‌اتکا نمی‌شود.

## سطح فعلی

این قابلیت روی کد `main` فعال است، اما هنوز وب‌پنل مشترک یا deployment مرکزی ندارد.
برای دسترسی چندکاربره باید در مرحله بعد یک صفحه intake احراز هویت‌شده روی سرویس
قابل‌اعتماد ساخته و deploy شود. تا آن زمان روش معتبر، اجرای محلی یا تحویل فایل در
تسک کنترل‌شده است.
