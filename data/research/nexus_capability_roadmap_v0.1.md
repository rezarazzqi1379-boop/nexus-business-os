# NEXUS Capability Forge & Cross-Domain Roadmap v0.1

Status: INTERNAL / RESEARCH + ENGINEERING PLAN. This document is not production authority and does not authorize external actions.

Canonical coordination basis: NEXUS Master Context v1.9 + Source Registry v1.6. Existing project engineering/acceptance masters retain their authority scopes. Dynamic facts must still be refreshed from live evidence before consequential use.

## Operating principle

NEXUS should be broad in what it can remember and investigate, but narrow and measured in what it actually installs or promotes. Every capability follows:

`Problem → Existing mechanism → Repeated gap? → Search catalog → Reverse-engineer/build/connect only if needed → Acceptance test → Sandbox/regression → Measure → Keep/Adopt/Defer/Retire → Rollback`

This prevents two opposite failures: forgetting useful technologies that may matter later, and bloating the runtime with tools/agents that do not improve outcomes.

## Cross-domain capability map

### Executive / Portfolio
Current strength: Canonical Authority v2, Portfolio Control Plane, project isolation, evidence classification and safe-action gating.
Next focus: convert portfolio state into a measurable internal work queue without granting consequential autonomy.

### Commercial / Growth
Current strength: Customer Network, Need Radar, Gmail/CRM evidence, supplier/customer role separation and project-specific sourcing workflows.
Build next: one evidence-bound opportunity funnel that deduplicates entities, scores need/fit and prepares next internal actions while outreach remains approval-gated.
Future expansion: adjacent-industry discovery, buyer demand signals, supplier alternatives, market/regulatory changes and repeat-business learning.

### Engineering
Current strength: canonical project masters and project-specific acceptance/review packets.
Build next: reusable requirement-delta engine that maps supplier proposal fields to buyer-controlled requirements and emits FACT/CLAIM/UNKNOWN/contradiction status without transferring values between project IDs.

### Coding / AI Engineering
Current strength: GitHub, CI, governed worker contract, OpenCode shadow lane, Model/Runner Arena and persistent Agent Catalog.
Build/benchmark next: isolated Coding Sandbox Vertical comparing baseline vs OpenAI Sandbox Agents/OpenCode/OpenHands/other candidates on the same frozen task. Adoption requires measurable improvement, not benchmark marketing.

### Memory / Context
Current strength: Master Context, Source Registry, project indexes, file provenance and GitHub artifacts.
Research next: versioned experiential memory/skills that can improve repeated work without becoming authority, leaking between projects or rewriting history. Stateful-memory systems such as Letta are research candidates, not automatic replacements for canonical memory.

### Research / Technology Discovery
Current strength: Technology Radar, persistent Agent Catalog, Agent Catalog Scout and primary-source verification policy.
Expand continuously: keep agent/framework/MCP/protocol/memory/eval/browser/computer-use/sandbox/automation candidates searchable with lifecycle and revisit triggers.

### Automation / Durable Execution
Current strength: scheduled tasks, queue/idempotency concepts, approval classes and internal safe work.
Deferred until measured need: heavier durable execution systems such as Temporal/LangGraph. Revisit when repeated state loss, multi-day workflow volume or recovery defects become measurable.

### Security
Current strength: conservative approval boundaries, prompt-injection tests and historical exact-action/ingress guard work.
Highest-priority convergence: transplant and prove untrusted-ingress isolation + exact-payload approval invalidation on current main before increasing autonomous external-action capability.

### Design / Brand
Current strength: tested design-token/accessibility package and draft-capable Canva/Figma paths.
Hold: approved ATF Asset Registry remains pending; no generated design becomes canonical brand/signature authority without asset hashes/roles approval.

### Deployment / Production
Current gap: deployment existence/green CI is not production proof; historical Railway login-loop evidence remains unresolved.
Repair later with staging/shadow proof: health, auth, persistence, rollback and observability must all be demonstrated before production promotion.

### Communication
Current strength: latest-thread reading, duplicate-outreach checks, project evidence packets and exact approval policy.
Goal: NEXUS prepares nearly all outbound work itself but shows the exact foreign-language payload + Persian explanation before consequential send.

## Research candidates added to long-horizon watch

- Letta / Letta Agents SDK / Letta Code — stateful long-lived agents, memory and git-backed context management; potentially relevant to NEXUS memory/continuity, but must not replace canonical authority. Research/benchmark only.
- CrewAI — multi-agent/workflow framework with memory, checkpointing, A2A and sandbox support; high overlap with NEXUS orchestration, so retain in catalog and benchmark only if a concrete workflow gap emerges.
- PydanticAI — typed Python agent framework candidate for schema-heavy agent contracts/evals; retain for future benchmark where stronger type/model validation would measurably reduce defects.
- Browser-use / computer-use stacks — retain for future read-only browser verticals when connectors do not cover a required workflow. Must be isolated and side-effect gated.
- OpenHands/OpenCode/OpenAI Sandbox Agents — highest-priority coding execution candidates because they directly map to a repeated current problem and can be evaluated on repository truth.

## Measurement model

The project should become more impressive by improving measurable operating capability, not by agent count. Track at least:

- percentage of internal work completed without manual intervention;
- correction burden per deliverable;
- evidence coverage and unresolved-UNKNOWN closure rate;
- duplicate outreach / cross-project contamination / security regression count;
- time from signal to reviewable decision packet;
- coding task success, regressions, time and cost under identical snapshots;
- opportunities discovered that progress to qualified conversations/orders/gross margin;
- recovery success after interruption and reproducibility from recorded evidence.

## Guardrail

Broad catalog ≠ broad authority. Research, reverse engineering, code generation and sandbox testing can expand aggressively; send/merge/deploy/production/pay/sign/order/publish/access-change/destructive actions remain exact approval gates.
