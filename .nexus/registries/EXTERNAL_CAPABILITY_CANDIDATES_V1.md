# NEXUS External Capability Candidate Register v1 — 2026-10-07

Purpose: preserve externally discovered capability clues without granting authority or installing unproven runtimes.

## Governance
Lifecycle: DISCOVERED -> STUDIED -> SANDBOXED -> ABLATED -> ADMITTED | REJECTED.
A repository, README, star count, demo or benchmark is a CLAIM/EVIDENCE clue, never production authority.
Promotion requires a measured NEXUS bottleneck, source/code review, failure-history review, acceptance test, sandbox proof and ablation win.
High-overlap candidates donate patterns; they do not create a second orchestrator.

## Acceptance directions
Extraction: unique qualified evidence gain, provenance completeness, selector validation, false-positive rate, latency/token/API cost.
Evaluation: regression detection gain, tool-selection error detection, root-cause usefulness, deterministic fault coverage, cost.
Observability: trace completeness, token/cost attribution, failure localization, overhead, data exposure risk.
Research: primary-source recovery, citation validity, contradiction detection, duplicate/no-progress prevention, bounded cost.
