# NEXUS Project-Wide Coordination v0.1

Date: 2026-08-23
Status: shadow coordination policy on PR #35.

## Objective
Apply the same evidence, authority, routing, measurement and learning rules across the whole NEXUS portfolio without flattening different domains into one generic workflow.

## Stable project-wide loop

`UNDERSTAND -> RETRIEVE -> VERIFY -> PRIORITIZE -> ASSEMBLE MISSION TEAM -> EXECUTE SAFE STEP -> TEST -> RECORD -> MEASURE -> LEARN`

## Portfolio coordination rules

1. Every active project gets a canonical `project_id`, domain, state, evidence quality, authority status, value, urgency, downside risk and attention cost.
2. WAITING projects remain watch-only unless a new signal changes state; this prevents duplicate outreach and artificial activity.
3. Procurement/engineering work without authoritative decision-critical requirements is `authority_first`, not execution-first.
4. Low-evidence projects become `research_first` even if strategically attractive.
5. Projects with measured outcomes move to `optimize`; architecture is judged against baseline results.
6. New projects without outcome evidence run the smallest safe executable step and must capture an outcome before scaling.
7. Portfolio priority includes opportunity cost and human attention, not only nominal value.
8. External consequential actions still pass through exact human approval.

## Current portfolio application

### Hydrotester
Primary mode: engineering/procurement.
Known project-wide lesson: heat-treatment dimensions must not leak into hydrotester authority; pressure/geometry evidence must remain source-separated. Recovered Yaxing/KARAT material is useful supplier evidence, not buyer authority.
Target proof: fewer late clarifications and unsupported technical claims.

### KCl
Primary mode: procurement/compliance/commercial intelligence.
Target proof: evidence-linked supplier/compliance status, no premature qualification, improved time-to-comparable commercial decision.

### Can forming
Primary mode: engineering/procurement.
Current waiting rule remains important where revised evidence has already been requested. Preserve the distinction between retrofit/forming scope and full-line quotations.
Target proof: fewer scope mismatches and no duplicate supplier outreach.

### Coffee / food additives / new opportunities
Primary mode: research/opportunity validation until verified commercial demand, regulatory route and economics exist.
Target proof: opportunity precision and board-ready evidence without false numeric confidence.

### DesignOps / websites / content
Primary mode: design/marketing/product.
Use domain-specific QA; do not force engineering gates onto design work. Human visual disagreement becomes regression evidence.
Target proof: fewer revisions, higher fidelity and shorter release cycles.

### NEXUS engineering itself
Primary mode: research/software/operations.
All self-improvement remains proposal -> branch/sandbox -> regression -> measured comparison -> promotion gate. CI success proves implementation integrity, not business value.

## Project-wide metrics

Track at least:
- duplicate action/outreach rate;
- unsupported claim rate;
- stale-authority error rate;
- cross-project contamination rate;
- late-blocker rate;
- human correction rate;
- false completion rate;
- time-to-decision;
- opportunity usefulness/precision;
- supplier qualification precision;
- workflow rework rate;
- context/tool overhead where measurable.

## Growth rule
A capability, agent, integration, database, dashboard or protocol is added only if it improves a measured outcome, closes an observed reliability gap, or enables a required capability that the current system cannot provide. More components are not counted as progress by themselves.
